# Database

PostgreSQL/Supabase schema is defined only by ordered files in `supabase/migrations`.

## Entities

- `profiles`: Auth projection, role, active flag.
- `fabrics`: normalized searchable material record with case-insensitive article uniqueness.
- `fabric_assets`: private photo/texture metadata; one texture per fabric; unique storage path.
- `configuration_groups/options`: шесть data-driven групп опций костюма; ткань не является option group и хранится через `configurations.fabric_id`.
- `configurations`: fabric reference and validated JSONB option map.
- `fabric_imports`: import counts, status, duplicate strategy and content hash for idempotency.
- `audit_log`: append-only actor/action/entity metadata generated by triggers.

## Integrity

PostgreSQL enforces nonblank article/name, nonnegative numeric/count fields, JSON object settings, valid active group/option pairs, FK protection, timestamps and audit. Search uses btree filters plus trigram indexes for article/name.

## RLS

All exposed tables have RLS. Auth actor is derived from `auth.uid()` and active profile. Employees read catalog and own configs; tailors manage fabric workflow; admins have Stage 1 administration. Direct API role checks improve errors but never replace RLS.

## Storage

`fabric-assets` is private, max 10 MB, JPEG/PNG/WebP allowlist. DB metadata and storage object policies both require authorized roles. Upload API validates decoded signatures before writing an object and removes the object if metadata insertion fails.

## Testing and types

`supabase/tests/database_test.sql` checks schema, indexes, triggers, seed and exact policy sets. Run `pnpm db:reset`, `pnpm db:test`, `pnpm db:types`. Generated `database.types.ts` is canonical and reproducibly refreshed with `pnpm db:types`; relation aliases derive from generated table rows.
